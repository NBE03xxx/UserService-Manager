# ロードマップ

この文書の v0.x は機能範囲を段階的に定義するロードマップ番号であり、公開packageのSemVerとは分けて扱う。v0.1の機能範囲は製品版 v1.0.0、v0.2はv1.2.0、v0.3はv1.3.0に対応する。v1.1.0は欠番。

## v0.1 — 安全な閲覧と基本操作（完了）

- `.service` の限定発見、明示登録、再スキャン
- 一覧、状態、詳細
- start/stop/restart、enable/disable
- user manager の daemon-reload
- unit で絞った journal 表示
- ユーザー領域外参照の表示のみ制御
- 日本語/英語の locale 自動切替
- 設定スキーマと拡張可能な backend/capability 境界
- Ubuntu 26.04 LTS を第一検証環境とする受入試験

完了条件は `TEST_PLAN.md` の v0.1 リリース基準による。

## v0.2 — 作成・編集の安全基盤（v1.2.0で実装）

- GUI での `.service` 新規作成
- 元 service ファイルの編集
- 保存前の構造検査と systemd 自身による可能な範囲の検証
- daemon-reload との安全な連携
- 変更前バックアップの確認（自動ではなく利用者選択）

## v0.3 — drop-in とライフサイクル（v1.3.0で実装）

- `systemctl --user edit` 相当の制限を持つ override 作成・編集
- 複数 drop-in（例: `10-environment.conf`）の閲覧・管理
- service の削除、復元可能なバックアップ導線
- 変更差分と検証結果のプレビュー

## v0.4 — systemd ユニット拡張

- `.timer`、`.socket`、`.path`
- 関連ユニットの関係表示
- ユニット種別ごとの操作能力と状態表示

## v1.x — 別スケジューラと成熟化

- cron を別バックエンドとして追加
- アプリ設定からの手動言語選択
- 高度なログフィルター、診断エクスポート
- 対応ディストリビューションの検証拡大

## ロードマップ原則

後続機能は v0.1 の安全境界を弱めない。編集・削除は検証、確認、バックアップ方針が揃うまで導入しない。各段階で新しい要件 ID とテストケースを追加し、追跡表を更新する。
