# ロードマップ

この文書のv0.xは実装済み機能範囲を段階的に定義したロードマップ番号であり、公開packageのSemVerとは分けて扱う。v0.1の機能範囲は製品版v1.0.0、v0.2はv1.2.0、v0.3はv1.3.0に対応する。v1.1.0は欠番。

## v0.1 — 安全な閲覧と基本操作（完了）

- `.service` の限定発見、明示登録、再スキャン
- 一覧、状態、詳細
- start/stop/restart、enable/disable
- user manager の daemon-reload
- unit で絞った journal 表示
- ユーザー領域外参照の表示のみ制御
- 日本語/英語の locale 自動切替
- 設定スキーマと拡張可能な backend/capability 境界
- Ubuntu 26.04 LTS を第一検証環境とする受入試験

完了条件は `TEST_PLAN.md` の v0.1 リリース基準による。

## v0.2 — 作成・編集の安全基盤（v1.2.0で実装）

- GUI での `.service` 新規作成
- 元 service ファイルの編集
- 保存前の構造検査と systemd 自身による可能な範囲の検証
- daemon-reload との安全な連携
- 変更前バックアップの確認（自動ではなく利用者選択）

## v0.3 — drop-in とライフサイクル（v1.3.0で実装）

- `systemctl --user edit` 相当の制限を持つ override 作成・編集
- 複数 drop-in（例: `10-environment.conf`）の閲覧・管理
- service の削除、復元可能なバックアップ導線
- 変更差分と検証結果のプレビュー

## 将来構想 — 必要性を再評価した場合のみ

- `.timer`、`.socket`、`.path`の発見・表示・操作
- 関連ユニットの関係表示
- ユニット種別ごとの操作能力と状態表示
- システムサービスを含む管理範囲の再検討
- 高度なログフィルター、診断エクスポート
- Ubuntu以外を含むDebian系ディストリビューションでの検証拡大

これらは現状のユーザーサービス管理には過剰であるため、版や期限を割り当てない。管理対象の規模や利用目的が変わり、必要性が具体化した時点で要件・安全境界から再検討する。

## 実装計画に含めない項目

- cronバックエンド
- アプリ内の手動言語選択

現在の利用目的では不要と判断した。言語はsystem localeによる日本語・英語の自動選択を維持する。

## ロードマップ原則

将来構想を実装する場合もv0.1〜v0.3の安全境界を弱めない。対象範囲を拡大する前に、必要性、要件、脅威モデル、検証環境を改めて定義する。
