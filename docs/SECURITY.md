# セキュリティ設計

## 1. セキュリティ目標

- root 権限や `sudo` を使用しない
- 表示のみサービスへの変更操作を確実に阻止する
- パス、リンク、ユニット名、設定の差し替えによる認可回避を防ぐ
- コマンド注入と意図しないユニット操作を防ぐ
- journal や詳細表示からの機密情報露出を抑える

## 2. 信頼境界と脅威

ユニットファイル、シンボリックリンク、systemd の返却値、journal、アプリ設定は全て検証対象の外部入力とみなす。主な脅威は、悪意あるユニット名、リンクの領域外誘導、スキャン後の差し替え、解析不能な ExecStart、他ユーザーが書込可能なファイル、巨大ログによる資源枯渇、エラー表示への秘密値混入である。

## 3. 操作認可

変更操作は次の全条件を操作直前に満たす場合だけ許可する。

1. canonical unit ID が有効な `.service` 名である
2. systemd user manager に現在も認識される
3. 明示登録済みである
4. ユニット実体とユーザーワークロード・設定が許可範囲内であり、領域外の実行基盤は信頼基準を満たす
5. リンク解決に循環・不存在・領域外遷移がない
6. 対象操作が service の capability に含まれる

不明は許可と解釈せず、表示のみに倒す。UI のボタン無効化だけでなく、Application Service 層でも拒否する。

`daemon-reload` は個別サービスを変更する操作ではないため、個別unitのread-only状態と切り離す。現在ユーザーのuser managerへ正常接続中で、全体メニューから明示確認した場合だけ実行し、system managerへフォールバックしない。

## 4. パス判定

- `~` や相対表現を絶対パスへ正規化する
- シンボリックリンクを最終実体まで解決し、最大深度を設ける
- 文字列 prefix ではなくパス要素境界で配下判定する
- 参照先を unit definition、system runtime、user workload、configuration/data、unresolved/dynamic に分類する
- system runtime は Ubuntu のパッケージ管理、root 所有、一般ユーザー書換不能を確認できる場合に限り領域外でも許容する
- user workload と configuration/data は許可されたユーザー領域内であることを要求する
- ホーム内でも他ユーザー書込み可能、用途不明、解決不能なら警告または表示のみとする
- 補助範囲はホーム内の明示選択ディレクトリに限定する
- `/tmp` 等の一時・共有領域は補助範囲として既定拒否する

## 5. プロセス・API 呼出し

D-Bus を優先する。CLI を使う場合はシェルを介さず、固定された実行ファイルに検証済み引数配列を渡す。環境変数、locale、タイムアウト、出力上限を明示する。標準エラーは診断用に上限付きで保持する。

## 6. データとプライバシー

設定は XDG ユーザー設定領域へ最小限保存する。journal は読み取るだけで複製しない。Environment の値、認証トークン、完全なプロセス環境は既定表示しない。診断情報をコピーする際は秘密を含む可能性を警告し、既知キーをマスクする。

## 7. 監査可能性

アプリ内部の診断ログには時刻、操作種別、unit ID、成功/失敗、エラー分類を記録できるが、journal 本文や秘密値は記録しない。永続診断ログを導入する場合は後続版で明示的な保持方針を定める。

## 8. 未解決事項

systemd の指定子・環境展開をどこまで安全に評価できるか、D-Bus と CLI の対応範囲、パッケージ由来を確認する具体的方法、ホーム内の所有権・モードに対する閾値は技術スパイクで確定する。確定までは解析不能を表示のみとする。

## 9. v0.2のファイル変更境界

- エディターは`~/.config/systemd/user/`直下のcanonical `.service` だけを作成・編集する。
- 編集は自己所有、通常ファイル、group/other書込不可の対象に限定し、symlinkは追跡しない。
- 事前検証を通過した内容だけを保存し、ファイルリビジョンが変化した場合は上書きしない。
- 一時ファイルとバックアップはmode 0600で作成し、対象の置換とディレクトリのfsyncを行う。
- systemd検証は`/usr/bin/systemd-analyze`をshellなしの引数配列で起動し、15秒timeout、64 KiB出力上限、固定locale/PATHで実行する。`--recursive-errors=no`により検証対象自身の警告を失敗とし、他unitの無関係な警告で保存を阻害しない。user managerと現在ユーザーの解決に必要な`XDG_RUNTIME_DIR`、session bus、HOME、USER/LOGNAMEだけは許可リストで引き継ぐ。
- 新しく作成したサービスは従来どおり明示登録するまで管理対象にならない。
