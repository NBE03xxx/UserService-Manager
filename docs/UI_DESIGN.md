# UI 設計

## 0. ビジュアルコンセプト

テーマは **「おしゃれな午後の喫茶店でのひととき」** とする。静かな午後の自然光、木のテーブル、陶器のカップ、珈琲とミルクの色合いを連想させる、温かく落ち着いた画面を目指す。装飾を増やすのではなく、十分な余白、穏やかな色、丁寧な階層表現によって上質さを出す。

トップには透明背景の、受け皿に載ったコーヒーカップの茶系単色に近い線画アイコンを96px相当の大きさで表示する。ライトはクリーム、木、くすみセージ、ダークは深いボルドー、コーヒー、真鍮を基調とし、背景に控えめな斜め格子を重ねる。情報カードは無地を保ち、可読性と状態識別を優先する。トップ文言は「ユーザーサービスマネージャー」、副題は「〜ごゆっくりどうぞ〜」とする。

### デザイン原則

- GNOME/libadwaita の操作慣習を尊重し、独自テーマで標準部品の意味を変えない
- 背景は温かなアイボリー、主要面はミルク色、強調色は珈琲色または落ち着いた琥珀色を候補とする
- 角丸、影、境界線は控えめにし、カードを過剰に並べない
- 状態色はテーマ色より意味を優先し、文字とアイコンを必ず併用する
- ログや診断情報は長時間読める中立的な面を使い、雰囲気のために可読性を下げない
- アニメーションは短く静かにし、システムの「視覚効果を減らす」設定を尊重する
- ライトとダークの双方で同じ雰囲気とコントラストを保てるトークン構造にする

### 初期デザイントークンの方向性

具体的な色値はモックアップとコントラスト検証後に確定する。実装では色を画面ごとに直書きせず、`surface`、`surface-raised`、`text`、`accent`、`success`、`warning`、`danger`、`readonly` 等の意味トークンとして管理する。珈琲色を警告・失敗色の代用にはしない。

### 外観モード

設定画面に「システム設定に従う」「ライト」「ダーク」の選択肢を置く。初回起動時は「システム設定に従う」とし、GNOME の外観設定が変わった場合は実行中にも可能な範囲で追従する。ライトまたはダークを選択した場合はその指定を優先し、再起動後も保持する。

切替時にウィンドウの再起動を要求せず、選択状態、フォーカス、スクロール位置、実行中操作を保つ。テーマ変更を、成功・警告・失敗・表示のみ等の業務状態の変化として扱わない。

- ライト: 午後の自然光、アイボリー、ミルク、明るい木材を基調とする
- ダーク: 夜間テーマではなく、光量を落とした喫茶店をイメージし、深い焙煎色と温かな低彩度色を基調とする
- 両モードで同じ情報階層と意味トークンを使い、単純な色反転は行わない

## 1. 情報構造

### メイン画面

- ヘッダー: 「サービス一覧」と動的な「管理対象 ○件」、再スキャン、発見済みサービスの管理登録、全体メニュー
- フィルター: 全て／実行中／停止中／表示のみ、テキスト検索
- 一覧: サービス名、Description、Active、Enable、可操作性
- 詳細ペイン: status、ユニットパス、ExecStart、制限理由、操作、ログへの導線

ウィンドウ幅が狭い場合は一覧から詳細ページへ遷移し、広い場合は二ペイン表示とする。

## 2. 操作

管理可能な登録済みサービスに start/stop/restart と enable/disable を表示する。現在状態に不適切な操作は無効化する。表示のみサービスでは全変更操作を無効化し、「参照先がユーザー管理範囲外です」など具体的理由を示す。

`daemon-reload` はサービス個別操作と混同しない全体メニューに置き、影響を説明して確認する。

## 3. 発見と登録

「サービスを追加」はファイル作成ではなく、発見済み未登録サービスを選ぶ画面であることを明記する。候補ごとにパス、Description、可操作性を示し、複数選択登録を可能にする。起点外のファイルを選ぶファイルピッカーは v0.1 では提供しない。

削除または一時的に認識不能となった登録済みサービスは「見つからない」として一覧に残し、操作を無効化する。再出現時は登録状態を自動復元する。利用者が明示的に「管理対象から解除」した場合だけ登録情報を削除する。

## 4. 状態とフィードバック

- 読込中: 行またはペイン単位の進捗。既存情報を可能なら保持
- 操作中: 対象行を busy にし、競合ボタンを無効化
- 成功: 状態再取得後に短い通知
- 失敗: 人向け要約、再試行、コピー可能な診断詳細
- 空状態: 未登録／一致なし／journal なしを区別
- 古い状態: 最終更新時刻と更新ボタンを表示

## 5. ログ画面

選択サービス名を固定表示し、更新、さらに読込、コピーを提供する。日時、優先度、メッセージを表示し、検索は表示済み範囲を対象とする。Environment 等の機密値を詳細画面や診断へ無条件展開しない。

## 6. 確認方針

- stop/restart/disable: 対象と影響を明示する確認（将来「次回から省略」を検討可能）
- daemon-reload: 常に確認
- start/enable: 原則即時実行し、進行中表示と取消不能の説明を適切に行う

## 7. アクセシビリティ

状態を色だけで表現しない。全操作にアクセシブル名とツールチップを付け、論理的フォーカス順、十分なコントラスト、拡大文字で崩れない配置を用いる。主要操作はキーボードで完結させる。

## 8. 文言例

| 状況 | 日本語 | English |
|---|---|---|
| 表示のみ | 表示のみ | Read only |
| 範囲外 | 参照先がユーザー管理範囲外です | A referenced path is outside your managed area |
| 再読込 | 再スキャン | Rescan |
| 登録 | 管理対象に追加 | Add to managed services |

## 9. ビジュアル検証

- 一覧、詳細、ログ、確認ダイアログ、空状態、エラー状態の代表モックアップを作成する
- Ubuntu 26.04 LTS の標準ライト・ダーク表示で確認する
- システム追従中の動的変更、手動ライト、手動ダーク、設定永続化を確認する
- 通常文字、状態表示、無効状態、フォーカス表示のコントラストを測定する
- 日本語・英語・長い疑似翻訳で余白と階層が崩れないことを確認する
- 「喫茶店らしさ」が操作性より前面に出ていないか、少人数のレビューで確認する

## 10. v0.2の作成・編集画面

- メインヘッダーの作成ボタンまたは`Ctrl+N`から新規エディターを開く。
- 各サービス行の編集ボタンから原ファイルを読み込む。symlink等の非対象は読込時に理由を示す。
- ユニット名、全文テキスト、バックアップ選択を1画面で確認できる。既存編集時はユニット名を変更できない。
- 「検証して保存」で事前検証し、成功後にのみ作成または更新、reload、バックアップ有無を確認する。
- 失敗時はエディターの内容を保持し、構造、systemd検証、外部競合、reloadのどの段階で失敗したかを文字で示す。

## 11. v0.3のdrop-in・ライフサイクル画面

- 各service行からdrop-in管理画面を開き、複数の`.conf`を一覧・作成・編集・削除する。
- service本体とdrop-inの保存確認には、systemd検証結果とスクロール可能なunified diffを表示する。
- drop-in削除は削除差分を提示してから明示確認する。
- service削除は「バックアップして削除」と表記し、停止・無効化が必要であること、本体とdrop-inが対象になることを確認画面に示す。
- 登録済みserviceが削除後にmissingとなった場合、行から最新バックアップの復元を開始できる。
- 復元は既存ファイルを上書きしないことを確認画面に示し、完了後にreload・再スキャンする。
