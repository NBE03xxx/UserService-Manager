# テスト計画

## 1. 方針

要件 ID を受入判定の基準とし、単体、統合、UI、セキュリティ、対象環境での受入試験を組み合わせる。実 systemd を変更する試験は隔離したテストユーザーと一時的な user unit で行い、実行前後の状態を記録して復元する。

## 2. テストレベル

- **単体**: パス正規化、能力、状態変換、locale、設定移行
- **統合**: systemd user manager、journal、永続化との境界
- **UI**: 登録、一覧、操作、表示のみ、エラー、キーボード
- **セキュリティ**: 注入、リンク差替え、領域外参照、設定改ざん、出力上限
- **受入**: Ubuntu/GNOME/Wayland の一般ユーザーセッション

## 3. 主要テストケース

| ID | テスト概要 | 期待結果 |
|---|---|---|
| TC-DISC-001 | 起点内の正常 service、読込エラー service、起点外の孤立 service を用意 | 正常 unit は候補、読込エラー unit は理由付き表示専用候補となり、起点外は表示されない |
| TC-DISC-002 | 登録、再起動、外部削除、再スキャン、再配置 | 登録保持後、消失時は missing・操作不能となり、再配置時に登録状態が自動復元される |
| TC-DISC-004 | missing の登録をユーザーが明示解除 | 登録情報が削除され、再出現しても自動登録されない |
| TC-DISC-003 | 外部で service を追加して再スキャン | 新しい未登録候補として現れる |
| TC-LIST-001 | active/inactive、enabled/disabled の複数 unit | 一覧と systemd 実値が一致する |
| TC-OPS-001 | start/stop/restart を順に実施 | 多重実行せず、各完了後の状態が一致する |
| TC-OPS-002 | enable/disable を実施 | 再取得した enable 状態が一致する |
| TC-OPS-003 | daemon-reload を実施 | 確認後に user manager のみへ実行し全体更新する |
| TC-OPS-004 | 操作中に unit を削除・差替え | 再検証で拒否し、分かるエラーを表示する |
| TC-INFO-001 | status、パス、ExecStart を表示 | 取得値と一致し、秘密値は既定非表示 |
| TC-LOG-001 | 対象 unit と別 unit にログを生成 | 対象 unit のログだけ表示し永続複製しない |
| TC-PATH-001 | ホーム内の通常ファイルとホーム内リンク | manageable と判定される |
| TC-PATH-002 | ホーム内リンクから `/usr/local` を参照 | read-only となり閲覧だけ可能 |
| TC-PATH-003 | 循環・壊れたリンク・解析不能参照 | unknown/read-only となり操作不可 |
| TC-PATH-004 | 補助範囲を追加 | 判定に使われるが service 発見範囲は増えない |
| TC-PATH-005 | `/usr/bin/python3` とホーム内スクリプトを指定 | Python が信頼基準を満たし他の参照先が許可範囲なら manageable となる |
| TC-PATH-006 | 一般ユーザーが書換可能な領域外ランタイムまたは領域外ワークロードを指定 | read-only となり理由が表示される |
| TC-SEC-001 | メタ文字を含む不正 unit ID | 入力拒否され、別コマンドが実行されない |
| TC-SEC-002 | スキャン後にリンク先を領域外へ差替え | 操作直前の再検証で拒否される |
| TC-SEC-003 | 他ユーザー書込み可能な設定を模擬 | 信頼せず安全に初期化または拒否する |
| TC-SEC-004 | 巨大 journal/標準エラーを返す | 上限内で処理し UI が応答を保つ |
| TC-UI-001 | 表示のみサービスを選択 | 操作が無効で理由が文字でも示される |
| TC-UI-002 | キーボードだけで主要フローを実行 | 登録、選択、操作、ログ閲覧が完了する |
| TC-UI-003 | ライト・ダーク、主要状態、日本語・英語の代表画面を視覚レビュー | 喫茶店コンセプトが一貫し、GNOMEの操作慣習、可読性、状態識別を損なわない |
| TC-UI-004 | 文字、状態、無効・フォーカス表示のコントラストと視覚効果低減を検査 | 採用するアクセシビリティ基準を満たし、視覚効果低減時も情報が失われない |
| TC-UI-005 | 初回起動、システム外観の動的変更、手動ライト／ダーク切替、再起動を実施 | 初期値はシステムに従い、追従中は変更が反映され、手動指定は優先・永続化される |
| TC-UI-006 | 操作中・詳細表示中・ログ閲覧中に外観を切り替える | 再起動せず切り替わり、選択、フォーカス、スクロール位置、操作状態が失われない |
| TC-ERR-001 | user bus/journal を利用不能にする | クラッシュせず要約・再試行・診断を示す |
| TC-I18N-001 | 日本語、英語、未対応 locale で起動 | 日本語、英語、英語フォールバックとなる |
| TC-I18N-002 | 翻訳カタログと疑似翻訳を検査 | 未翻訳・変数不整合・重大なレイアウト崩れがない |
| TC-ARCH-001 | mock backend と追加 unit type を試作 | UI が systemd CLI へ直接依存せず能力追加できる |
| TC-EDIT-001 | 新しいcanonical service名と検証済み内容を保存 | 発見起点にmode 0600の通常ファイルが原子的に作成され、reload後に発見される |
| TC-EDIT-002 | 既存serviceを読み込み、バックアップを選択して保存 | 元内容のバックアップを作成し、対象だけを更新してreload・再スキャンする |
| TC-EDIT-003 | 読込後に外部からserviceを変更 | リビジョン不一致で保存を拒否し、外部変更を上書きしない |
| TC-EDIT-004 | 構造不正、systemd検証失敗、過大ファイルを入力 | 理由付きで拒否し、対象ファイルを変更しない |
| TC-EDIT-005 | symlink、他者所有、共有書込可能なserviceを編集 | 安全性検査で拒否し、リンク先や別ファイルを変更しない |
| TC-UI-007 | キーボードだけで新規作成と既存編集を行い、検証失敗も確認 | 入力、バックアップ選択、確認、エラー理由へ到達できる |

## 5. v0.1 リリース基準

- Must 要件に対応する全テストが成功
- 未解決の重大・高リスク脆弱性がない
- Ubuntu/GNOME/Wayland の一般ユーザー環境で受入試験成功
- root、sudo、Polkit 昇格を要求しないことを確認
- 日本語・英語で重大な欠落・操作不能がない
- 既知の制約と対象外機能が README/リリースノートに明記される

## 6. テスト証跡

将来の実装リポジトリでは、テスト結果にアプリ版、OS、GNOME、systemd、locale、実行日時、テストケース ID を保存する。失敗は要件 ID と紐付け、仕様変更なら該当文書も同時更新する。

## 7. v0.2 リリース基準

- v0.1の既存Must要件とv0.2のFR-018〜022、SEC-008〜011、UI-007に対応する試験が成功
- 検証失敗、外部競合、symlink、reload失敗が安全側に縮退
- Ubuntu 26.04 LTSの一般ユーザーセッションで作成・編集・バックアップ・reloadを受入
- v1.1.0を欠番とし、製品版をv1.2.0とするメタデータが一致
