# 国際化設計

## 1. 対象言語

- `ja` 系 locale: 日本語
- その他: 英語（フォールバックを含む）

v0.1 は起動時に locale を判定する。後から設定で `system`、`ja`、`en` を選べるよう、設定モデルには `language_preference` を予約する。

## 2. 実装方針

gettext 等の GTK エコシステムに適合する翻訳カタログを用い、ユーザー向け文字列をコードから分離する。文字列結合で文章を組み立てず、複数形、置換、語順を翻訳単位で扱う。systemd の生の状態値と、翻訳した表示ラベルを分離する。

## 3. 翻訳対象

画面ラベル、ボタン、状態、通知、確認、エラー要約、アクセシブル名、ツールチップを翻訳する。ユニット名、ファイルパス、journal 本文、systemd の原文診断は翻訳せず、必要なら翻訳済み要約を併記する。

## 4. 表記規則

- 日本語: 簡潔な常体を基本とし、危険・失敗時は曖昧語を避ける
- 英語: sentence case、簡潔な能動態
- `start` 等は UI では「開始 / Start」、診断詳細では原語を保持
- 変数は引用または視覚的に区別し、翻訳文字列内の位置変更を許す

## 5. レイアウト

英語で文字列が伸びても切れないレスポンシブ配置を用いる。固定幅ボタンへの依存を避け、右から左の言語は v0.1 対象外だが、方向を固定する実装を避ける。日時は locale に従い、journal の機械的タイムスタンプは内部で一貫した形式を保持する。

## 6. 検証

- `LANG=ja_JP.UTF-8` と英語 locale で全主要画面を確認
- 未翻訳キー、空訳、プレースホルダー不一致を自動検査
- 長い疑似翻訳で切れ・重なりを確認
- キーボードニーモニックと支援技術ラベルを両言語で確認
- system locale 不明・未対応時に英語へ安全にフォールバックすることを確認

外観モードの選択肢と説明も翻訳対象とし、言語設定と外観設定は独立して保持する。言語変更の将来実装が外観設定を初期化しない構造とする。
